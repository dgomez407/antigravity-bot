# 9. Strict Artifact Resolution

Date: 2026-07-01

## Status

Accepted

## Context

When an Antigravity IDE agent session starts, it can sometimes take a moment for the session title to synchronize or for artifacts to be generated. Previously, if LazyGravity could not match the active session title to a known conversation ID in the local `.gemini/antigravity/brain` directory, it fell back to using `artifactService.getLatestConversationWithArtifacts()`.

Because the Antigravity IDE (and by extension the Gemini brain) stores all conversations centrally, this fallback meant that a completely new session would incorrectly bind its Discord channel to the most recently active *past* agent session. As a result, when users clicked "Open" on an Implementation Plan in Discord, LazyGravity would fetch and display the `implementation_plan.md` from an older, unrelated conversation. This led to confusing UI breadcrumbs (e.g. `.gemini > antigravity > brain > ...`) in the IDE when these unrelated artifacts were opened.

## Decision

We have removed the `getLatestConversationWithArtifacts()` fallback from:
1. `src/bot/index.ts`: When persisting the active `conversation_id` for a channel.
2. `src/events/interactionCreateHandler.ts`: When fetching the artifact contents on Discord interaction.
3. `src/ui/artifactsUi.ts`: When populating the /artifacts dropdown.

LazyGravity must now strictly rely on `artifactService.findConversationByTitle(sessionTitle)` to map the session. If no exact match is found, the system correctly reports "No artifacts found" rather than hallucinating artifacts from unrelated sessions.

## Consequences

- **Accuracy**: Users will only ever see artifacts generated by the actual active IDE session.
- **Security & Privacy**: Prevents bleeding of sensitive artifacts (like implementation plans or logs) from one project into the Discord channel of another project.
- **UX Dependency**: Artifact rendering in Discord now strictly depends on the Antigravity IDE properly saving its `overview.txt` (which updates the title). Before this completes, artifact menus will gracefully show empty states.
